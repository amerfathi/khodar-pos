# BRAKA 2.6.13 — release candidate, not production certified

Checkpoint: 2026-10-03. No production deployment has occurred at this checkpoint.

## Changes

- Company-specific business-clock storage; invalid timezones are rejected before persistence. Settings edits no longer change the clock before the aggregate commits.
- Invoice time and accounting date use the same company timezone.
- Server timezone updates require a company-owner tenant session and update tenant metadata in the same D1 batch as the sync event.
- Device enrollment races cannot replace another registered device proof.
- Cash-shift replay verifies tenant/branch drawer ownership and ordered staged opening, source movement, closing and next opening.
- Unfinished cashier endpoints and shift-bearing sync events fail closed unless `CASH_SHIFTS_ENABLED=true` is explicitly configured. Do not enable this flag in production yet.
- Preserve the existing restore conflict-key contract for older installed clients while cash shifts remain staged.
- Match Web/Desktop/Android version identifiers: 2.6.13 / Android 26130. Automated release-version check added.
- Safe dependency updates; production dependency audit reports zero advisories. Development/build tools still report 14 high and 1 moderate advisory; no forced major upgrade performed.
